## Why quote remains disabled

The evidence above proves that 4.1.12.55 contains native quote-related UI and
protocol code, but it does not establish any of the contracts required for a
safe in-process call:

- constructor and destructor addresses for `kernel::ReferSendData`;
- exact object size, alignment, field offsets, and string ownership rules;
- the concrete send entry point and its calling convention;
- required thread/task-runner context;
- result callback lifetime and mutation boundary;
- a second independent source that validates each recovered address.

Calling a candidate with any of those values guessed can corrupt the live
process or duplicate a message. Therefore `/status` reports
`capabilities.quote=false`, and `/SendQuoteMsg` deterministically returns
`rejected / unsupported_weixin_build` while preserving request-id idempotency.

## Evidence needed to continue

At least one of the following is required before enabling the mutation path:

1. the exact matching PDB identified above;
2. a trustworthy 4.1.12.55 implementation with source and independently
   verifiable signatures;
3. a controlled debugger trace from an isolated 4.1.12.55 process that covers
   construct, send, callback, and cleanup, plus an independent static match.

Old offsets from the upstream 4.1.10.27 project are explicitly rejected.
